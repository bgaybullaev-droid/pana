Этот документ описывает Блок D - пять задач по реализации Telegram-нативных механик. Это та категория функциональности, которая отличает UcharMarket от веб-конкурентов (Joymee, BirBir, OLX). Все они либо отдельные приложения, требующие установки, либо веб-сайты. UcharMarket работает как Telegram WebApp, что даёт уникальные преимущества по удержанию пользователя и виральности - но только при условии, что эти преимущества реально использованы.

Без задач Блока D продукт работает технически, но теряет своё позиционное преимущество. Пользователь, который запускает UcharMarket через классический поиск в Telegram, видит обычный TWA, неотличимый от любого другого. С задачами Блока D он видит продукт, в котором каждая Telegram-возможность работает на удержание - Menu Button мгновенного запуска, Inline-кнопки в уведомлениях, Deep Links с предзаполненными фильтрами, бот-автопостинг для риелторов, нативный поиск через бот.

Версия V2.0 учитывает несколько важных решений по сравнению с предыдущей версией. Во-первых, в D2 убран вариант "внутреннего чата в TWA" как нереалистичный для MVP - кнопка "Написать продавцу" открывает прямой Telegram-чат с риелтором с предзаполненной фразой. Во-вторых, в D4 (бот-автопостинг) добавлены автообновление поста (по кнопке риелтора) и автоудаление при снятии объявления - это делает функцию полноценной, а не "минимальной". В-третьих, D5 расширена: помимо Inline Mode в любом чате, появляется поиск через форму ввода прямо в боте с компактными результатами и переходом в TWA. В-четвёртых, добавлен сквозной принцип языковой консистентности с выбором языка при первом запуске бота.

## Языковая консистентность

Принципиальное правило, действующее во всех задачах блока D и за его пределами: вся коммуникация с пользователем ведётся на языке, выбранном пользователем в настройках. Это включает UI-тексты, описания объявлений, push-уведомления, результаты поиска, кнопки экспорта, тексты автопостинга и системные сообщения. Никаких смешанных языков в одном экране, никаких русских вкраплений в узбекский интерфейс.

При первом нажатии /start в боте пользователь видит приветствие на трёх языках одновременно (русский, узбекский кириллица, узбекский латиница) и кнопки выбора с названиями: "Русский", "O'zbekcha", "Ўзбекча". До явного выбора используется язык интерфейса Telegram пользователя как fallback (ru → русский, uz → узбекский, другие языки → русский по умолчанию).

Смена языка возможна в любой момент через UI в TWA (раздел "Настройки → Язык") и через команду /language в боте. При смене - UI и AI-описания мгновенно переключаются на новый язык (AI-генерация уже создала версии на трёх языках через F1). Исторические push-уведомления остаются на языке, на котором были отправлены, не пересылаются. Будущие push-уведомления приходят на новом языке.

Особый случай - коммуникация между двумя пользователями (предзаполненная фраза для "Написать продавцу" в D2): используется язык отправителя, не получателя. Покупатель пишет на своём языке, риелтор получает на этом же языке. Дальше переписка идёт между ними напрямую в Telegram, мы не вмешиваемся.

## Особенность D1 и D4

Особое место в блоке занимают D1 и D4. D1 (Menu Button) - это базовая настройка через BotFather плюс приветствие с выбором языка, но эффект на UX огромный: одна кнопка вместо команды /start. D4 (бот-автопостинг с автообновлением и автоудалением) - это центральная функция подписки Кабинет риелтора (99 000 сум в месяц), без неё подписка теряет основную ценность. Эти две задачи - наибольшая отдача на затраченное время в блоке.

D5 в новой версии получает повышенный приоритет за счёт основного функционала "поиск в боте через форму ввода" - это главный путь использования Telegram-нативной функциональности для аудитории, которая привыкла искать через бота, а не через TWA.

## Оглавление

- **D1.** Menu Button бота → открытие TWA, выбор языка при первом запуске
- **D2.** Inline Keyboard в push-уведомлениях
- **D3.** Deep Links для маркетинга
- **D4.** Бот-автопостинг с автообновлением и автоудалением
- **D5.** Поиск в Telegram (форма в боте и Inline Mode)

# D1. Menu Button бота, открытие TWA и выбор языка при первом запуске

## Контекст и зачем это нужно

Сейчас пользователь запускает UcharMarket в Telegram через команду /start или через прямую ссылку. Это работает, но создаёт лишний шаг: нужно сначала открыть бота, затем найти команду или нажать на сообщение, затем дождаться открытия TWA. Для пользователя, который заходит в бота 2-3 раза в день, это раздражающее трение.

Telegram Bot API предлагает простое решение: Menu Button (синяя кнопка в нижней части чата с ботом). При настройке этой кнопки на TWA - один тап мгновенно открывает приложение. Никаких команд, никакого поиска сообщений. Кнопка всегда видна, всегда работает.

Помимо Menu Button, в D1 включается выбор языка при первом запуске. Это важная часть онбординга: язык, выбранный здесь, применяется ко всему дальнейшему общению с пользователем во всех контекстах продукта (см. сквозной принцип языковой консистентности в intro).

Это самая быстрая и одна из самых эффективных задач всего pre-launch периода. Базовая настройка через BotFather - около часа работы. Эффект на UX повторных открытий - огромный. Это именно та задача, которую нужно сделать первой в Блоке D, чтобы получить мгновенный win и сразу увидеть улучшение в поведении пользователей.

## Состояние ДО

Запуск приложения - через команду /start в боте, либо через прямую ссылку из других мест. Menu Button в боте либо отсутствует, либо настроен на стандартное меню с командами. Языковой выбор при первом запуске не запрашивается.

## Состояние ПОСЛЕ

### Конфигурация Menu Button

Через BotFather настраивается Menu Button бота:

- Тип: web_app (открывает TWA)
- URL: ссылка на TWA UcharMarket
- Текст кнопки: "Открыть UcharMarket" (или короче "Поиск" - решение по итогам визуального теста)

### Что видит пользователь в боте

В нижней части чата с ботом UcharMarket - синяя кнопка с заголовком. Она всегда видна, не скроллится вместе с чатом. Один тап мгновенно открывает TWA в полноэкранном режиме.

### Поведение при первом /start (онбординг с выбором языка)

Когда пользователь впервые нажимает /start (через переход по ссылке, через приветственное сообщение, через ручной ввод команды) - бот показывает приветствие на трёх языках одновременно с кнопками выбора:

- Текст: "Добро пожаловать в UcharMarket! / Xush kelibsiz UcharMarket'ga! / Хуш келибсиз UcharMarket'га!"
- Подзаголовок: "Выберите язык / Tilni tanlang / Тилни танланг:"
- Inline Keyboard с тремя кнопками: "Русский", "O'zbekcha", "Ўзбекча"

Выбранный язык сохраняется в настройках пользователя в БД, применяется ко всему дальнейшему общению. После выбора - сообщение редактируется на короткое подтверждение на выбранном языке плюс приглашение открыть приложение через Menu Button.

### Fallback язык до явного выбора

Если пользователь почему-то не нажал ни одну кнопку (закрыл диалог, ушёл, отвлёкся) - до явного выбора используется язык интерфейса Telegram пользователя:

- language_code = "ru" → русский
- language_code = "uz" → узбекский кириллица (как более распространённая раскладка)
- другие коды → русский по умолчанию

Telegram передаёт language_code пользователя в initData каждой сессии TWA и в данных пользователя в боте. Это надёжный fallback, не требующий дополнительных запросов.

### Смена языка позже

Пользователь может сменить язык в любой момент:

- Через TWA: "Настройки → Язык", выбор из трёх вариантов
- Через команду в боте: /language - бот показывает то же приветствие с тремя кнопками выбора

При смене языка все последующие коммуникации (UI в TWA, push-уведомления, описания объявлений, результаты поиска) переключаются на новый. Исторические push-уведомления остаются на языке, на котором были отправлены.

### Поведение Menu Button для разных пользовательских сценариев

- **Новый пользователь:** нажал на ссылку из рекламы, попал в чат с ботом. Видит приветствие с выбором языка (см. выше). После выбора - видит Menu Button. Один тап - в приложении.
- **Возвращающийся пользователь:** хочет посмотреть новые объявления. Открывает чат с ботом, видит Menu Button (всегда), один тап - в приложении на выбранном им языке.
- **Пользователь после push-уведомления:** получил push, прочитал, хочет открыть приложение. Тап на Menu Button - в приложении (альтернатива к открытию через само сообщение, см. D2 для inline-кнопок).

## Что НЕ входит в задачу

- Сложная логика приветствия (видео-онбординг, туториал) - простое сообщение с выбором языка
- Кастомизация цвета или иконки Menu Button - Telegram сам определяет стиль
- Разные Menu Button для разных пользователей (B2C, B2B) - не нужно, ведём всех в один TWA, дальше внутри определяется роль

## Edge cases

- **Пользователь заблокировал бота:** если пользователь когда-то заблокировал бота, потом разблокировал - Menu Button должен работать как для всех. Если пользователь раньше выбирал язык - сохранённый язык применяется. Если не выбирал - снова показываем выбор при следующем /start.
- **Старая версия Telegram:** Menu Button с типом web_app поддерживается во всех актуальных версиях Telegram. Очень старые версии могут не поддерживать - в этом случае пользователь видит обычное текстовое меню. Это допустимая деградация - таких пользователей мало.
- **Пользователь нажал /start повторно после первого выбора языка:** если язык уже выбран - не показываем диалог выбора заново, просто показываем приветственное сообщение на сохранённом языке с Menu Button. Чтобы поменять язык - явно вызвать /language.
- **Пользователь начал говорить с ботом без /start:** некоторые пользователи попадают в чат с ботом и сразу пишут текст. Если язык ещё не выбран - применяем fallback по language_code Telegram, не блокируем разговор. Можем добавить ненавязчивую подсказку "Можете выбрать язык командой /language".
- **Изменение URL TWA:** если URL TWA меняется (например, домен или путь) - Menu Button нужно перенастроить через BotFather. Желательно избегать смены URL после публичного запуска - все настройки указывают на стабильный URL.
- **Тестовый и продакшен бот:** если есть отдельный тестовый бот (для разработки) - у него Menu Button настраивается отдельно с тестовым URL. Не путать настройки.

## Связи с другими задачами

**Зависит от:** A6 (i18n - тексты приветствия и кнопок проходят через словарь, в данном случае на трёх языках одновременно).

**Связано с:** D3 (Deep Links - другая механика входа в приложение, дополняет Menu Button), все остальные задачи блока D и за его пределами зависят от выбранного языка пользователя.

## Критерии готовности

- Menu Button бота настроен через BotFather на открытие TWA
- Текст кнопки выбран и согласован
- Кнопка работает на iOS, Android и Telegram Desktop
- Один тап открывает TWA в полноэкранном режиме без промежуточных экранов
- При первом /start показывается приветствие на трёх языках с inline-кнопками выбора
- Выбранный язык сохраняется в БД и применяется ко всем последующим коммуникациям
- Fallback на основе language_code Telegram работает до явного выбора
- Команда /language работает - запускает повторный выбор языка
- Смена языка через TWA в Настройках работает
- Конфигурация задокументирована для возможного восстановления при необходимости

# D2. Inline Keyboard в push-уведомлениях

## Контекст и зачем это нужно

Push-уведомления в UcharMarket - центральный канал удержания B2C-пользователя. Сохранил поиск "2-комнатные в Чиланзаре до 35 000 у.е.", получаешь уведомления о новых подходящих объявлениях. Это работает - но если каждое уведомление требует от пользователя открыть приложение, изучить карточку, нажать "избранное" или "связаться" - получается высокое трение. На каждый клик отдельная сессия.

Telegram Bot API даёт инструмент Inline Keyboard - кнопки прямо под сообщением, которые выполняют действия без открытия приложения. Под уведомлением о новом объявлении прикрепляются две кнопки: "В избранное" и "Написать продавцу". Тап - и действие выполнено, ничего не открывается, пользователь продолжает заниматься своими делами в Telegram.

Это даёт два эффекта. Первый - удобство для пользователя: меньше ритуала на каждое объявление. Второй, не менее важный - поведенческие сигналы для рекомендательной системы. Когда пользователь жмёт "В избранное" - это сигнал для AI-матчера (см. Ф-77, Ф-78). Когда жмёт "Написать продавцу" - это ещё более сильный сигнал интереса. Чем чаще пользователь делает действия, не выходя из ленты Telegram, тем точнее становится персонализация.

Это не замена для открытия приложения - детальный просмотр и Крутилка работают только в TWA. Но это снимает трение для быстрых решений по предложенным объявлениям.

## Состояние ДО

Push-уведомления о новых объявлениях приходят как обычные сообщения в боте: текст и фото объявления. Чтобы выполнить любое действие (добавить в избранное, написать продавцу, открыть детали) - нужно открыть TWA, найти объявление в ленте, выполнить действие.

## Состояние ПОСЛЕ

### Структура push-уведомления

Каждое push-уведомление о новом объявлении - сообщение в боте с тремя элементами:

- Главное фото объявления (если есть)
- Текст с ключевыми параметрами и кратким AI-описанием (см. F1) на языке пользователя
- Inline Keyboard с кнопками действий (см. ниже)

### Inline-кнопки

- **В избранное:** добавляет объявление в избранное пользователя. После нажатия - сообщение редактируется, кнопка меняется на "В избранном". Если пользователь тапает повторно - убирает из избранного, кнопка возвращается к исходному состоянию.
- **Написать продавцу:** открывает прямой Telegram-чат с риелтором с предзаполненной первой фразой (см. ниже).
- **Подробнее (опционально):** открывает TWA с детальной карточкой этого объявления через Deep Link (см. D3). Это страховка для пользователей, которые хотят полный контекст перед действием.

### Реализация кнопки "Написать продавцу"

При нажатии кнопки открывается прямой Telegram-чат с риелтором (через ссылку tg://resolve?domain=username или t.me/username, а в TWA - через Web App API метод openTelegramLink). Никакого "внутреннего чата UcharMarket" нет - в Фазе 1 такая возможность не реализуется.

### Предзаполненная первая фраза

Это критическое требование, без которого функция теряет половину пользы. При открытии чата с риелтором поле ввода уже содержит фразу, готовую к отправке. Формат:

- Шаблон: "Здравствуйте! Увидел в UcharMarket ваше объявление: [тип, район, краткие параметры]. Хочу узнать подробнее."
- Пример: "Здравствуйте! Увидел в UcharMarket ваше объявление: 3-комн в Чиланзаре, 65 м², 35 000 у.е. Хочу узнать подробнее."

Включение упоминания "UcharMarket" в фразу - не случайность. Это даёт три эффекта: (1) для риелтора - явный трекинг источника лида (откуда пришёл клиент), (2) для нашего бренда - органическое упоминание в каждом обращении, (3) для покупателя - естественный контекст разговора.

Технически Telegram поддерживает предзаполненный текст через параметр URL: t.me/username?text=... Текст должен быть URL-encoded. В TWA-контексте используется метод openTelegramLink, который тоже принимает URL с параметрами.

### Язык предзаполненной фразы

Фраза формируется на языке покупателя (отправителя сообщения), не риелтора (получателя). Это правильно: покупатель пишет на своём языке, риелтор получает текст на этом же языке. Дальше переписка идёт между ними напрямую в Telegram, мы не вмешиваемся. См. сквозной принцип языковой консистентности в intro.

Если у риелтора в кабинете другой язык - это его проблема понять (большинство риелторов в Узбекистане понимают и русский, и узбекский на бытовом уровне). Если в будущем появятся конфликты - можно добавить автоматический перевод предзаполненной фразы, но в Фазе 1 это не нужно.

### Поведенческие сигналы

Каждое действие через Inline-кнопку записывается как событие для рекомендательной системы:

- "В избранное" - сильный позитивный сигнал по типу/району/цене этого объявления
- "Написать продавцу" - очень сильный позитивный сигнал (показывает реальное намерение)
- Игнорирование уведомления (нет реакции в течение N часов) - слабый негативный сигнал, влияет на снижение веса похожих объявлений в дальнейших уведомлениях

Эти сигналы должны передаваться в тот же интерес-вектор пользователя, который формируется на основе действий внутри TWA. Не должно быть двух отдельных систем (для in-app действий и для bot-действий).

## Что НЕ входит в задачу

- Внутренний чат UcharMarket с риелтором - в Фазе 1 не делаем
- Кастомные эмодзи на кнопках - используем стандартные текстовые лейблы
- Inline-кнопки в других типах сообщений (например, системных уведомлениях о статусе аккаунта) - только для уведомлений об объявлениях
- Автоматический перевод предзаполненной фразы на язык риелтора - только язык отправителя

## Edge cases

- **Объявление снято с публикации:** если пользователь нажал "В избранное" по уведомлению, а объявление к этому моменту уже снято - сообщение редактируется на "Это объявление уже неактуально". Кнопки убираются.
- **Risk: риелтор не использует Telegram активно:** некоторые риелторы могут не отвечать на сообщения в Telegram, потому что у них основной канал связи - звонки. На push-уведомлении это не проблема (мы не обещаем мгновенного ответа), но в общении - да. Решение: добавить ещё кнопку "Позвонить" с tel: ссылкой на номер риелтора. Это уже часть функциональности контактов, не блокер D2.
- **Race condition при двойном тапе:** пользователь быстро тапает "В избранное" два раза. Первый тап добавляет, второй должен либо ничего не делать (проверка состояния на бэкенде), либо убрать из избранного (toggle). Выбираем toggle - это естественное поведение для этой кнопки.
- **Уведомление пришло, пользователь его не открыл:** через какое-то время пользователь видит уведомление, тапает "В избранное". Если объявление за это время изменилось (цена снижена) - использовать актуальные данные на момент тапа, не сохранённые в момент отправки уведомления.
- **Telegram отозвал inline-кнопки:** редкий случай: Telegram может отзывать inline-кнопки на старых сообщениях (политика хранения). Если кнопки больше не работают на сообщении старше определённого срока - не считаем это багом, нормальное поведение Telegram.
- **Группировка нескольких уведомлений:** если у пользователя срабатывает 5 разных сохранённых поисков одновременно (например, после большой партии новых объявлений) - не отправлять 5 отдельных уведомлений. Группировать в одно сообщение "5 новых объявлений по вашим поискам" с кнопкой "Открыть" в TWA.
- **Действие "Написать продавцу" для парсерного объявления (без claim):** если объявление - парсерное (не Мастер-запись), то контакт продавца - из источника. Если у нас есть Telegram-username из источника - открываем чат с ним. Если есть только телефон - кнопка "Написать продавцу" не показывается, вместо неё - "Позвонить продавцу" с tel:-ссылкой.
- **У риелтора несколько привязанных номеров (через C4):** если у риелтора есть выбор контактного номера для каждого объявления (см. C4) - для каждого объявления используется тот номер/контакт, который выбран риелтором при его создании. Это уже учтено на уровне данных объявления.
- **Предзаполненный текст не работает в каком-то клиенте Telegram:** некоторые версии или клиенты могут игнорировать ?text=... параметр. Это редкий случай, графейс-фейл - чат всё равно открывается, просто без предзаполненной фразы. Не блокирует функцию.
- **Username риелтора пустой:** у риелтора в Telegram может не быть username (только phone-only аккаунт). В этом случае открыть чат через @username нельзя. Решение: показывать только кнопку "Позвонить" вместо "Написать продавцу", или использовать tg://user?id=... ссылку (требует Telegram-id риелтора в БД).

## Связи с другими задачами

**Зависит от:** A4 (механика push-уведомлений уже существует, мы расширяем её добавлением Inline-кнопок), F1 (краткое AI-описание в карточке push на языке пользователя).

**Связано с:** D3 (Deep Links используются в кнопке "Подробнее"), C4 (выбор контактного номера риелтора для конкретного объявления учитывается), персонализация (Ф-77, Ф-78 - сигналы от Inline-действий идут в тот же вектор интересов).

## Критерии готовности

- Push-уведомления о новых объявлениях содержат Inline Keyboard минимум с двумя кнопками: "В избранное" и "Написать продавцу"
- Кнопка "В избранное" работает как toggle (повторный тап убирает)
- Кнопка "Написать продавцу" открывает прямой Telegram-чат с риелтором с предзаполненной фразой
- Предзаполненная фраза включает упоминание UcharMarket, тип, район и краткие параметры объявления
- Предзаполненная фраза формируется на языке пользователя-отправителя
- Сообщение редактируется после действия "В избранное", отражая изменённое состояние
- Все действия через Inline-кнопки записываются как поведенческие сигналы для персонализации
- Edge cases (снятое объявление, race conditions, парсерные контакты, отсутствие username) обработаны корректно

# D3. Deep Links для маркетинга

## Контекст и зачем это нужно

В Telegram есть специальный механизм Deep Links для ботов: ссылка вида t.me/ucharmarket_bot?start=PAYLOAD открывает чат с ботом и автоматически отправляет команду /start с указанным payload. Бэкенд бота получает payload и может выполнить любое действие: открыть конкретное объявление, применить фильтры, перевести в нужный раздел, привязать пользователя к рекламной кампании, активировать реферальный код.

Без Deep Links маркетинг работает по слабой модели: пользователь видит рекламу "Найди 2-комнатную в Чиланзаре" → переходит по ссылке → попадает в общий чат с ботом → должен сам найти, как применить фильтр "2 комнаты" + "Чиланзар". Конверсия с такой воронки низкая, потому что между рекламой и ценностью - три-четыре пользовательских действия.

С Deep Links: пользователь видит ту же рекламу → переходит по ссылке t.me/ucharmarket_bot?start=chilanzar_2rooms → попадает прямо в TWA с уже применёнными фильтрами. От рекламы до ценности - один тап. Это многократно повышает конверсию рекламного бюджета.

Дополнительные сценарии использования: claim-инвайты для риелторов ("ваши объявления уже у нас, нажмите чтобы подтвердить"), реферальные ссылки между пользователями, ссылки на конкретные объявления для шеринга в социальных сетях, маркетинговые кампании с трекингом источника.

## Состояние ДО

Запуск приложения происходит без передачи параметров: либо через Menu Button (D1), либо через универсальную ссылку без payload, либо через команду /start без аргументов. Любые контекстные действия (открыть конкретный объект, применить фильтр) пользователь выполняет уже внутри приложения вручную.

## Состояние ПОСЛЕ

### Поддерживаемые форматы payload

Бэкенд бота должен распознавать и корректно обрабатывать следующие категории payload-ов. Каждая - со своим префиксом для однозначности.

- **obj_<object_id>:** открыть приложение с детальной карточкой конкретного объявления. Используется для шеринга объявлений в соцсетях, мессенджерах. Пример: t.me/ucharmarket_bot?start=obj_12345
- **filter_<filter_string>:** открыть ленту с применёнными фильтрами. Filter_string - это закодированный набор параметров. Используется для маркетинга. Пример: t.me/ucharmarket_bot?start=filter_chilanzar_2rooms_buy
- **ref_<user_id>:** реферальная ссылка. При первой регистрации нового пользователя по такой ссылке - реферал записывается в систему. Используется для будущей реферальной программы. Пример: t.me/ucharmarket_bot?start=ref_98765. На MVP реферальная программа не активирована (см. Блок F), но ссылки уже работают и записывают source.
- **claim_<user_id>:** персональная инвайт-ссылка для риелтора при ручном онбординге. При переходе - сразу показывается раздел Found с предложением подтвердить найденные объявления. Используется в B2B-онбординге первых 20-30 риелторов (см. E5). Пример: t.me/ucharmarket_bot?start=claim_98765
- **agent_<channel_id>:** инвайт-ссылка для риелтора, найденного через Telegram-канал. Аналогично claim, но для случая когда риелтор не найден по номеру, но идентифицирован по каналу. Пример: t.me/ucharmarket_bot?start=agent_realestate_tashkent
- **inv_<invoice_id>:** (заглушка для Фазы 2) - ссылка для инвойса/оплаты. На MVP не активна, но префикс зарезервирован чтобы не было конфликтов в будущем.

### Логика обработки

При получении сообщения /start с payload бэкенд:

- Парсит payload, определяет категорию по префиксу
- Для нового пользователя - сначала запускает выбор языка (см. D1), payload сохраняется в state и применяется после выбора
- Для obj_ и filter_ - открывает TWA с соответствующим контекстом через initData или query-параметры
- Для ref_ - проверяет, что пользователь новый, записывает source, продолжает обычный онбординг. Если пользователь уже зарегистрирован - игнорирует ref payload, идёт обычный flow
- Для claim_ и agent_ - проверяет, что user_id совпадает с предполагаемым, после регистрации перенаправляет в раздел Found
- Для неизвестных или некорректных payload - открывает TWA в обычном режиме, не показывает ошибку (тихая деградация)

### Аналитика и трекинг источников

Каждый Deep Link, по которому пришёл пользователь, должен быть учтён в системе аналитики. Минимум - какой payload использовался, дата перехода, был ли новый или возвращающийся пользователь. Это нужно для оценки эффективности маркетинговых кампаний и каналов привлечения.

## Что НЕ входит в задачу

- Создание UI для генерации Deep Links в кабинете риелтора - это для шеринга, не блокирует MVP, добавляем позже
- Сложная аналитика (когорты, LTV по источникам) - простой счётчик переходов на старте
- A/B тестирование разных payload-форматов - оптимизация после запуска
- Реферальная программа сама по себе - только префикс ref_ работает, выплаты/бонусы - Фаза 2

## Edge cases

- **Объявление, на которое ссылается obj_, удалено или снято:** TWA открывается, показывает экран с сообщением "Это объявление больше не актуально" и кнопкой "Перейти к похожим объявлениям". Не падать, не показывать пустую карточку.
- **Filter payload содержит несуществующий район:** если в payload указан район, которого нет в системе (например, опечатка в маркетинговой ссылке) - применить остальные понятые фильтры, неизвестные параметры игнорировать, лента работает.
- **Claim/agent payload использован посторонним пользователем:** риелтор переслал свою персональную ссылку другу. Друг переходит. Проверка user_id не совпадает. Решение: открыть обычный онбординг (не показывать раздел Found), записать в логи факт некорректного использования. Не блокировать.
- **Очень длинный payload:** Telegram ограничивает payload до 64 символов. Если этот лимит превышен - использовать сокращения или хранить параметры на бэкенде с коротким ID-ключом.
- **Безопасность payload:** payload приходит от пользователя, может быть изменён. Никогда не доверять payload как авторитетному источнику данных. Любые действия (выдача claim, привязка реферала) - только после проверки соответствия пользователю.
- **UTM-параметры из веб-рекламы:** если ссылка приходит из веб-рекламы с UTM-параметрами - они теряются при переходе в Telegram. Решение: на лендинге перед редиректом в Telegram - формировать payload с закодированными UTM. Это часть E4 (маркетинговые материалы), но требует поддержки в D3.
- **Deep link сработал, но пользователь не выбрал язык:** если пользователь новый и пришёл по Deep Link - сначала выбор языка (D1), затем применение payload. Payload сохраняется в state до завершения выбора.

## Связи с другими задачами

**Зависит от:** A1 (claim-флоу должен работать к моменту использования claim_ ссылок), B3 (унифицированная поверхность поиска - filter_ ссылки ведут на канонический роут), D1 (выбор языка должен произойти до применения payload для новых пользователей).

**Связано с:** D2 (кнопка "Подробнее" в push-уведомлении использует obj_ Deep Link), E4 (маркетинговые материалы используют filter_ ссылки), E5 (ручной онбординг риелторов - использует claim_ ссылки).

## Критерии готовности

- Все 6 префиксов payload (obj, filter, ref, claim, agent, inv) распознаются и корректно обрабатываются
- Обработка некорректных или неизвестных payload не приводит к ошибкам, тихая деградация
- Каждый переход по Deep Link учитывается в аналитике с указанием payload и пользователя
- Безопасность: payload не доверяется напрямую, любые привилегированные действия - после проверки
- Для новых пользователей выбор языка происходит до применения payload
- Edge cases (удалённые объекты, опечатки в фильтрах, чужие claim-ссылки) обработаны корректно
- Документация по форматам payload готова для команды маркетинга

# D4. Бот-автопостинг с автообновлением и автоудалением

## Контекст и зачем это нужно

Это центральная функция подписки Кабинет риелтора (99 000 сум в месяц). Без неё подписка теряет основную ценность.

Реальность работы риелторов в Узбекистане: у каждого активного риелтора есть свой Telegram-канал с базой подписчиков (от нескольких сотен до нескольких тысяч). Когда появляется новое объявление, риелтор вручную копирует фото, пишет текст, постит в свой канал. Когда меняется цена или другие параметры - снова руками идёт в канал и редактирует пост. Когда продаёт объект - снова руками удаляет или помечает как проданное. Это занимает много времени и постоянно требует помнить о существовании канала.

UcharMarket предлагает полную автоматизацию жизненного цикла поста. Добавьте бота администратором в свой канал, и при создании объявления в кабинете - бот сам публикует его в ваш канал. При изменении объявления - риелтор может одной кнопкой обновить пост в канале. При снятии объявления - бот сам корректно его обработает (удалит или пометит как проданное). Только ваши объявления, форматированные единообразно, со ссылкой на детальную карточку в UcharMarket.

Это даёт двойную ценность. Первая - риелтор экономит часы рутины и больше не забывает обновлять канал при изменениях. Вторая - его подписчики начинают переходить в UcharMarket по ссылкам, мы получаем органический трафик от каждой публикации. Это работает на обе стороны: риелтор автоматизирует свой канал, мы получаем целевую B2C-аудиторию.

## Состояние ДО

Подписка Кабинет риелтора в архитектуре заложена (см. C3), но конкретная функциональность не реализована. Риелторы вручную копируют объявления из кабинета в свои Telegram-каналы, вручную обновляют посты при изменениях, вручную удаляют посты при продаже.

## Состояние ПОСЛЕ

### Подключение канала

В кабинете риелтора - раздел "Автопостинг" (доступен только при активной подписке Кабинет; в Фазе 1 - доступен всем риелторам, по завершении тестового периода - только подписчикам).

Процесс подключения:

- Риелтор вводит username своего канала (например, @realestate_tashkent)
- Система проверяет, что канал существует и публичный
- Инструкция риелтору: "Добавьте бота @ucharmarket_bot администратором вашего канала с правом публикации сообщений"
- После добавления риелтор нажимает "Проверить подключение". Система делает тестовую публикацию (или проверочный запрос). Если успешно - канал привязан к аккаунту
- Опции: можно отключить канал в любой момент кнопкой "Отключить автопостинг"

### Автопубликация при создании объявления

При создании нового объявления в кабинете (или при подтверждении через claim из A1) - бот автоматически публикует его в подключённом канале риелтора. Формат поста:

- Главное фото объявления
- Текст: AI-сгенерированный (см. F1) на языке риелтора. Тип объекта, район, ключевые параметры (площадь, комнаты, этаж), цена, краткое описание
- Inline-кнопка "Подробнее" с Deep Link на детальную карточку (obj_<id> через D3)
- Подпись внизу: "Через @ucharmarket_bot" - небольшая, ненавязчивая. Это виральный элемент.

Чекбокс "Опубликовать в моём канале" при создании объявления (по умолчанию включен, можно снять). Это даёт риелтору контроль - не каждое объявление он хочет дублировать в канал.

### Автообновление поста (через кнопку риелтора)

Когда риелтор изменяет объявление в кабинете (цена, описание, параметры, фото) - пост в канале автоматически НЕ обновляется. Вместо этого появляется индикация устаревания и кнопка "Обновить пост в канале".

Visual indication устаревшего поста:

- На карточке объявления в "Мои объявления" - значок и подсказка "Пост в канале устарел. Обновить"
- В разделе "Автопостинг" - badge с количеством устаревших постов

Без push-уведомлений о необходимости обновить - это создавало бы спам.

Кнопка "Обновить пост в канале" доступна:

- На карточке объявления в "Мои объявления"
- В разделе "Автопостинг" в списке публикаций

Простой клик - бот обновляет пост через Telegram Bot API (editMessageText, editMessageMedia), показывает тост "Пост в канале обновлён".

### Ограничения Telegram при редактировании

Важное техническое ограничение Telegram: после 48 часов с момента публикации сообщения media (фото/видео) редактировать нельзя. Текст редактируется без ограничений по времени. Это ограничение Telegram, не наше.

Если риелтор изменил фото объявления и хочет обновить пост старше 48 часов - перед обновлением показываем модал:

- Текст: "Фото в посте изменилось, но Telegram не позволяет менять фото в постах старше 48 часов. Что сделать?"
- Кнопка 1: "Обновить только текст" - текст в посте обновляется, фото остаётся прежним
- Кнопка 2: "Удалить старый пост и опубликовать новый" - старый пост удаляется (потеря накопленных просмотров и реакций), публикуется новый со свежим фото
- Кнопка 3: "Отмена"

Если изменилось только текстовое содержимое (без смены фото) - модал не показываем, просто обновляем текст без вопросов.

Это даёт риелтору осознанный выбор и явно сигнализирует, что ограничение - на стороне Telegram, не нашего сервиса.

### Автоудаление при снятии объявления

Когда риелтор переводит объявление в неактивный статус - бот автоматически обрабатывает пост в канале:

- **Статус "Продано" / "Сдано":** пост в канале НЕ удаляется. Вместо этого редактируется на "ПРОДАНО" (или "СДАНО") большим заметным текстом в начале + сохраняется основное содержимое для контекста. Это социальное доказательство - подписчики канала видят, что риелтор успешно закрывает сделки.
- **Статус "Пауза" / "Архив":** пост в канале удаляется (через deleteMessage). Объявление временно или навсегда не должно показываться, нет смысла оставлять в канале.
- **Удаление объявления:** пост в канале удаляется.

Telegram даёт удалять свои сообщения в любой момент, ограничений по времени нет. Так что автоудаление работает всегда.

## Что НЕ входит в задачу

- Real-time автообновление при любом изменении (без кнопки) - в Фазе 1 только manual trigger
- Автопостинг в Instagram, ВКонтакте и другие соцсети - только Telegram, нативный канал
- Поддержка нескольких каналов на одного риелтора - один канал на аккаунт в MVP
- Аналитика по постам в канале (просмотры, переходы из канала) - простой список с ссылками, без метрик
- Автопостинг в C2C-сегменте (для физлиц-продавцов) - только B2B
- Кастомизация шаблона поста риелтором - используется единый формат

## Edge cases

- **Бот удалён из канала риелтором:** риелтор по какой-то причине убрал бота из админов канала. Следующая попытка публикации или обновления завершится ошибкой Telegram API. Решение: уведомить риелтора в кабинете "Бот больше не имеет доступа к вашему каналу. Добавьте его снова или отключите автопостинг". Не пытаться публиковать снова до восстановления доступа. Старые посты в канале остаются как были.
- **Канал стал приватным:** риелтор изменил настройки канала. Если у бота есть права админа - публикация и обновление продолжают работать. Если бота нет в админах приватного канала - см. предыдущий кейс.
- **Канал переименован:** риелтор изменил username. У бота есть доступ через chat_id, не через username, поэтому публикация работает. Но в интерфейсе кабинета может отображаться старое имя - обновить при следующей сверке.
- **Превышен Telegram rate limit при автообновлении:** если риелтор быстро меняет много объявлений и нажимает "Обновить" - Telegram может ограничить частоту. Использовать очередь обновлений с паузами, не отправлять параллельно.
- **Объявление с большим количеством фото:** у объявления может быть 10-15 фото. В пост публикуем только главное (первое). Остальные доступны в детальной карточке (по ссылке). Альтернатива - media group в Telegram (до 10 фото в одном сообщении), но это сложнее в реализации, оставляем для расширения.
- **Длинное описание объявления:** если AI-сгенерированное описание длинное - обрезаем до разумного лимита (около 500-700 символов в посте) с многоточием. Полный текст - по ссылке "Подробнее".
- **Канал общетематический (не только недвижимость):** риелтор может иметь канал, в котором постит и недвижимость, и личные мысли. Бот публикует только наши объявления, не вмешивается в остальной контент. Это естественное поведение.
- **Дубль публикации:** если бот публикует объявление дважды (race condition или ошибка) - второй пост должен быть отменён или удалён. На уровне бэкенда - идемпотентность по object_id и channel_id.
- **Риелтор массово редактирует много объявлений:** если риелтор изменил 30 объявлений за раз (например, изменился курс UZS и он подкорректировал цены) - 30 индикаторов "пост устарел" появляются на 30 карточках. Это нормально, риелтор обновляет по одному. В будущем можно добавить кнопку "Обновить все устаревшие" - но не в Фазе 1.
- **Telegram API временно недоступен при автоудалении:** риелтор пометил объявление как "Продано", бот пытается отредактировать пост на "ПРОДАНО", Telegram API не отвечает. Поставить в очередь повторных попыток (retry с backoff). Если через несколько часов не получилось - оставить старый пост, уведомить админа.

## Связи с другими задачами

**Зависит от:** C3 (механизм подписки в архитектуре), D3 (Deep Links для кнопки "Подробнее" в постах), F1 (AI-сгенерированный текст для постов на языке риелтора).

**Влияет на:** органический рост B2C-аудитории через каналы риелторов, ценность подписки Кабинет (99 000 сум), B2B retention (риелторы, использующие автопостинг с автоматической поддержкой жизненного цикла, остаются дольше).

## Критерии готовности

- Риелтор может подключить свой Telegram-канал к аккаунту через инструкцию "добавь бота админом"
- Проверка подключения работает корректно
- При создании нового объявления (или claim) - оно автоматически публикуется в канал в стандартном формате
- Чекбокс "Опубликовать в моём канале" доступен при создании, можно снять
- Подпись "Через @ucharmarket_bot" присутствует в каждом посте
- Inline-кнопка "Подробнее" с Deep Link работает
- При изменении объявления показывается индикация устаревшего поста на карточке и в разделе Автопостинг
- Кнопка "Обновить пост в канале" работает в обоих местах
- При обновлении поста с изменённым фото старше 48 часов показывается модал с тремя вариантами действий
- При статусе "Продано/Сдано" - пост редактируется на "ПРОДАНО"/"СДАНО"
- При статусе "Пауза/Архив" или удалении - пост удаляется
- Edge cases (удалённый бот, rate limits, дубли, недоступность API) обработаны корректно
- История публикаций видна в разделе "Автопостинг" в кабинете

# D5. Поиск в Telegram (форма в боте и Inline Mode)

## Контекст и зачем это нужно

Эта задача объединяет два сценария поиска прямо в Telegram, без необходимости открывать TWA: основной - поиск через форму ввода в боте, дополнительный - Inline Mode в любом чате.

Поиск через форму ввода в боте - это центральный путь использования Telegram-нативной функциональности для значительной части аудитории. Многие пользователи привыкли искать через бота, а не через приложение. Они открывают чат с UcharMarket, пишут "2-комн Чиланзар до 35тыс" и ожидают увидеть результаты прямо в чате. Если этот путь не работает - они уходят к конкурентам.

Inline Mode - это виральный инструмент. Пользователь в любом чате (с другом, в группе) набирает @ucharmarket_bot 2комн Чиланзар - выпадает список объявлений, можно отправить карточку другу. Это особенно работает, когда человек ищет квартиру и часто советуется с семьёй или друзьями.

Раньше эта задача была только про Inline Mode с низким приоритетом. В V2.0 добавлен основной функционал (форма в боте) с высоким приоритетом. Inline Mode остаётся как дополнительная виральная механика.

Существенное усиление: fuzzy matching для обоих сценариев. Опечатки в названиях районов, транслитерация (Chilanzar → Чиланзар), морфологические формы - всё это обрабатывается, чтобы пользователь не получал пустой результат из-за мелкой ошибки в запросе.

## Состояние ДО

Поиск через форму в боте не реализован. Inline Mode у бота не настроен или настроен формально без полезной функциональности. Пользователь не может искать объявления, не открывая TWA.

## Состояние ПОСЛЕ

### Сценарий 1: Поиск через форму в боте (основной функционал)

Пользователь в чате с ботом UcharMarket может искать объявления одним из способов:

- **Кнопка "Поиск" в Reply Keyboard или Menu Button:** для интуитивности новичков. Видимая, всегда под рукой.
- **Просто текст в чате с ботом:** для продвинутых. Пользователь пишет "2-комн Чиланзар до 35тыс" в чат с ботом - бот воспринимает как поисковый запрос.

### Различение поискового запроса и обычного текста

Бот должен различать "Привет, как дела?" и "2-комн Чиланзар". Простой парсер на ключевые слова:

- Если в тексте есть район из словаря - считаем поисковым запросом
- Если в тексте есть число + "комн"/"комнат" - считаем поисковым запросом
- Если в тексте есть "купить", "продажа", "аренда", "снять" - считаем поисковым запросом
- Если в тексте есть конкретные цены ("30000", "35тыс", "до 50") - считаем поисковым запросом

Если ни один из критериев не сработал - тост "Не понял запрос. Попробуйте указать район или количество комнат." с кнопкой "Открыть поиск" (показывает форму ввода через Reply Keyboard).

### Что бот понимает в запросе

Гибкий парсинг текстовых запросов с учётом fuzzy matching:

- **Район:** "Чиланзар", "Юнусабад", "Чилонзар" (опечатка), "Chilanzar" (транслитерация), "ул. Амира Темура" (ландмарк) - всё распознаётся через fuzzy match по словарю районов и ландмарков.
- **Количество комнат:** "2комн", "3 комнаты", "1-комн", "двухкомнатная" - распознаются через числовой шаблон + морфологию.
- **Цена:** "до 30000", "от 50 тыс", "до $40k", "до 35тыс у.е." - распознаётся диапазон с возможной валютой.
- **Тип сделки:** "продажа", "аренда", "купить", "снять", "sotiladi", "ijara" (узбекский) - через словарь.
- **Тип объекта:** "квартира", "дом", "офис", "коммерческая", "xonadon" - через словарь.

### Формат результатов в боте

Возвращаем компактный список одним сообщением. Не множество отдельных сообщений (это спам). Структура:

- Заголовок: "Найдено: X объявлений"
- 5-10 первых объявлений в виде структурированного списка
- Внизу - кнопка "Открыть все результаты в приложении" со ссылкой в TWA через Deep Link (filter_<filter_string> через D3)

Формат каждой строки в списке - структурированная компактная запись с эмодзи как разделителями (необязательно, но удобно):

- "1. 3-комн, Чиланзар, 65м², 5/9 этаж - 35 000 у.е."
- "2. 2-комн, Юнусабад, 50м², 3/9 этаж - 28 000 у.е."

Каждая строка - кликабельная (через Markdown link), при клике - переход в TWA с детальной карточкой через obj_ Deep Link.

### Лимиты и сортировка

В сообщении показываем 5-10 первых результатов (наиболее релевантные). Полный список (до 100 результатов) доступен по ссылке "Открыть все в приложении" в TWA.

Сортировка - по релевантности (точное совпадение фильтров приоритетнее fuzzy match), при равной релевантности - по свежести.

### Сохранение поиска - только в TWA

В боте кнопка "Сохранить поиск" не показывается. Сохранение поисков работает только через UI в TWA (раздел "Сохранённые поиски"). Это упрощение для MVP - нет смысла дублировать функцию.

Можно добавить в боте подсказку "Чтобы получать уведомления о новых объявлениях по этому запросу - сохраните поиск в приложении" с переходом в TWA. Но это опционально.

### Сценарий 2: Inline Mode в любом чате

Через BotFather включается Inline Mode для бота. Настраивается:

- Placeholder text: "Введите запрос: район, комнаты, цена"
- Иконка/превью: используется аватар бота (стандартное поведение)

Запросы парсятся той же логикой, что и в сценарии 1 (с fuzzy matching).

Telegram API ограничивает количество inline-results до 50 в одном ответе. Возвращаем не более 20 результатов - более фокусированная выдача с лучшей релевантностью.

Формат каждого результата - карточка с фото, заголовком, описанием. При выборе - пользователь отправляет эту карточку в текущий чат. Отправленная карточка содержит фото, текст, и Inline-кнопку "Открыть в UcharMarket" с Deep Link (obj_<id> через D3).

Если запрос пустой ("@ucharmarket_bot " без текста) - показываем последние 10-20 объявлений как пример.

### Fuzzy matching (для обоих сценариев)

На MVP включаем fuzzy matching для двух категорий:

- **Опечатки и варианты в районах:** "Чилонзар" → "Чиланзар". Используем Levenshtein distance с порогом 1-2 правки для коротких слов, 2-3 для длинных.
- **Транслитерация ASCII ↔ Кириллица:** Chilanzar → Чиланзар, "Yunusabad" → "Юнусабад". Простая table-based transliteration или библиотека.
- **Морфологические формы (минимально):** "квартиры" / "квартиру" / "квартирка" - все распознаются как "квартира". Используем простую stemming-логику или предкомпилированный словарь форм.

Если запрос полностью не распознан даже после fuzzy - возвращаем сообщение "Не понял запрос. Попробуйте: район, количество комнат, цену".

### Язык запросов и результатов

Запросы парсятся независимо от языка (русский и узбекский в обеих раскладках). Словари районов и ключевых слов - на трёх языках.

Результаты возвращаются на языке пользователя (см. сквозной принцип в intro). Если язык интерфейса пользователя - русский, описания AI-генерации в результатах - на русском. Если узбекский - на узбекском (соответствующая раскладка).

## Что НЕ входит в задачу

- Сложный синтаксис запросов с операторами (AND, OR, скобки) - простой текстовый ввод
- Голосовой ввод запроса - стандартный текст
- Персонализация результатов в боте/Inline Mode (учёт интересов пользователя) - простая фильтрация на старте
- Сохранение поиска прямо из бота - только через UI в TWA
- Inline Mode для риелторов (поиск по своим объявлениям) - только B2C-поиск

## Edge cases

- **Запрос не парсится ни в один параметр:** пользователь ввёл что-то, что не распознаётся даже с fuzzy ("привет", "ужин", произвольный текст). Сообщение "Не понял запрос. Попробуйте: район, количество комнат, цену". Не возвращаем пустой список.
- **Очень общий запрос:** пользователь набрал просто "квартира" или "Ташкент" - матчится тысячи объявлений. Возвращаем первые 5-10 по дате (новые сначала) с подсказкой "Уточните район или количество комнат для более точных результатов".
- **Опечатка слишком серьёзная для fuzzy:** "Чнланзр" вместо "Чиланзар" - распознаётся. "Хчазнр" - не распознаётся (слишком далеко по Levenshtein). Возвращаем "Не понял запрос".
- **Запрос на узбекском латинице:** "2 xona Chilonzor" - распознаётся через словарь узбекских ключевых слов и fuzzy для районов.
- **Производительность Inline-запросов:** Inline Mode требует быстрого ответа (Telegram таймаут около 30 секунд, но реальная UX-ожидаемость - 1-2 секунды). Запрос к БД должен быть оптимизирован, использовать индексы и кэш. Fuzzy matching не должен сильно замедлять - предкомпиляция словаря возможных вариантов.
- **Кэширование результатов в Inline Mode:** Telegram кэширует inline-results на стороне клиента. Если объявление изменилось/удалено - в кэше может остаться старая карточка. Использовать короткое cache_time (60 секунд) в API ответе.
- **Безопасность и спам:** Inline Mode и форма в боте могут использоваться для спама. На стороне Telegram это контролируется самим клиентом. На нашей стороне - стандартные rate limits на пользователя.
- **Запрос приходит до выбора языка:** если новый пользователь сразу пишет в чат с ботом без /start и без выбора языка - сначала применяем fallback язык (по language_code), затем парсим запрос. Можно показать ненавязчивую подсказку "Выберите язык командой /language".
- **Результаты пусты:** fuzzy matching распознал параметры, но в БД нет совпадений. Сообщение "По вашему запросу пока нет объявлений. Попробуйте расширить параметры или сохраните поиск в приложении - мы пришлём уведомление, когда появится подходящее" с кнопкой в TWA.

## Связи с другими задачами

**Зависит от:** A7 (качество распознавания запросов зависит от словаря районов и логики парсинга, разработанных для парсера), F1 (описания в результатах - AI-сгенерированные на языке пользователя).

**Связано с:** D3 (отправленные карточки и кнопки "Открыть все" содержат Deep Links), B3 (форма поиска в боте использует тот же Effector-стор фильтров что и поверхность поиска в TWA), D1 (язык пользователя влияет на язык результатов).

## Критерии готовности

- Поиск через форму в боте работает: кнопка "Поиск" в Menu Button или Reply Keyboard, плюс распознавание любого текста как поискового запроса по ключевым словам
- Inline Mode активирован в BotFather и работает
- Запросы парсятся по 5 категориям: район, комнаты, цена, тип сделки, тип объекта
- Fuzzy matching работает для опечаток в районах, транслитерации и морфологических форм
- В боте возвращается компактный список 5-10 объявлений + ссылка "Открыть все в приложении"
- В Inline Mode возвращается до 20 результатов с возможностью отправить карточку в чат
- Каждый результат содержит ссылку или кнопку перехода в TWA через Deep Link (obj_<id>)
- Результаты на языке пользователя (русский / узбекский кириллица / узбекский латиница)
- Производительность - ответ за 1-2 секунды для типичных запросов
- Edge cases (нераспознаваемый запрос, пустые результаты, спам) обработаны корректно
