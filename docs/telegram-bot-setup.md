## 1. Что настраивается кодом, а что — руками в BotFather

Главный принцип: **всё, что можно поставить через Bot API, ставится кодом при
старте процесса** (идемпотентно, переживает пересоздание бота). В BotFather
остаётся только то, что Bot API менять не умеет.

| Параметр | Где настраивается | Деталь |
|---|---|---|
| **Menu Button** (кнопка-меню → открывает Mini App) | **Код** | `backend/app/bot/setup.py:set_menu_button` — `set_chat_menu_button(MenuButtonWebApp(...))`. Текст кнопки `MENU_BUTTON_TEXT = "UcharMarket"` (`setup.py:33`). URL берётся из `TELEGRAM_WEBAPP_URL`. |
| **Список команд `/`** (автокомплит) | **Код** | `backend/app/bot/setup.py:set_bot_commands` — `set_my_commands(...)` для локалей default/`ru`/`uz`. Команды: `/start /search /profile /language /help /cancel` (`_BOT_COMMANDS`, `setup.py:40-47`). |
| **Inline Mode** (`@ucharmarket_bot <запрос>` в любом чате) | **🔧 BotFather** (обязательно) | Bot API не включает inline-режим. Без флага BotFather inline-хэндлер зарегистрирован, но Telegram его не вызывает. Напоминание залогировано в `backend/app/bot/main.py:200-204`. |
| **Inline placeholder** (подсказка в поле inline) | **🔧 BotFather** | `/setinlinefeedback` не нужен; placeholder ставится через `/setinline` → текст **«Район, комнаты, цена»**. |
| **Имя / @username / аватар / описание / about** | **🔧 BotFather** | Бренд-настройки, Bot API их не трогает. |
| **Токен бота** | **🔧 BotFather** → env `TELEGRAM_BOT_TOKEN` | Создаётся в `/newbot`, ротация — `/token`. |

> ⚠️ Menu Button и список команд **намеренно НЕ настраиваются руками** — их
> ставит код. Если выставить их ещё и в BotFather, при следующем старте бот их
> перезапишет. Не дублировать.

## 2. Пошаговая настройка в BotFather (один раз на бота)

Открыть [@BotFather](https://t.me/BotFather) в Telegram.

### 2.1. Боевой бот
1. `/newbot` → задать имя и @username (текущий прод: `@ucharmarket_bot`,
   совпадает с подписью постов «Через @ucharmarket_bot»). Скопировать токен →
   в env `TELEGRAM_BOT_TOKEN` боевого деплоя.
2. **Включить Inline Mode:** `/setinline` → выбрать бота → ввести placeholder
   **`Район, комнаты, цена`**.
3. (Опц.) `/setdescription`, `/setabouttext`, `/setuserpic` — бренд.
4. **Команды и Menu Button НЕ трогать** — поставит код при старте (см. §1).

### 2.2. Отдельный тестовый бот (обязательно для e2e и 48h-spike)
Тест гоняем на **отдельном** боте и **отдельном** канале, чтобы не слать мусор
боевым пользователям и не палить прод-канал.

1. `/newbot` → например `@ucharmarket_test_bot`. Токен → в env тестового
   стенда (`TELEGRAM_BOT_TOKEN` тестового окружения, **не** боевого).
2. `/setinline` → тот же placeholder `Район, комнаты, цена`.
3. Тестовый канал: создать приватный канал, добавить тестового бота
   **админом** с правом постинга (как в инструкции D4 «добавь бота админом»).

### 2.3. Что в BotFather НЕ настраивается (чтобы не искать зря)
- Menu Button (ставит код), список команд `/` (ставит код).
- Тексты сообщений, лимиты бот-поиска/inline — это **админка**
  (страница `/admin/bot-limits`, см. FU3), не BotFather.
- Webhook/polling — бот работает на long-polling (`dp.start_polling`,
  `main.py:225`), вебхук не настраивается; на старте делается
  `delete_webhook(drop_pending_updates=True)`.

имена env регистронезависимы.

|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен из BotFather. Невалидный токен = бот падает на старте (health-probe `main.py:176-181`, фатально). | **Обязательно** |
| `TELEGRAM_BOT_USERNAME` | @username без `@`. Используется при сборке deep-link URL (`services/deeplink.py:_bot_username`). | **Обязательно** |

| `TELEGRAM_WEBHOOK_SECRET` | Секрет вебхука (если используется внешняя проверка). | Опц. |
| `APP_ENV` | `production` / `development`. Влияет на уровень логов misconfig (`setup.py:74`). | Да |
| `CABINET_SUBSCRIPTION_OPEN_TO_ALL` | `true` = D4-автопостинг открыт всем продавцам (фаза 1); `false` = только платная подписка Кабинет. Статус логируется на старте (`main.py:207-216`). | Да |

| `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` / `TELEGRAM_SESSION_NAME` | Telethon-креды **парсера каналов** (Блок A), не основного бота. | Парсер — да |

## 5. Ручной spike: лимит 48ч на замену медиа

**Зачем.** Модал «фото старше 48ч» (FU2/D4) опирается на ограничение Bot API на
`editMessageMedia`. Формулировки Telegram тоньше, чем «нельзя менять медиа после
48 часов», поэтому нужно подтвердить реальную границу на живом боте — от этого
зависит, оставлять модал или упростить.

**Процедура (на тестовом боте и тестовом канале из §2.2):**
1. Ботом опубликовать в тестовый канал пост с фото (через обычный путь
   автопостинга или вручную `sendPhoto`). Записать `message_id` и время.
2. Подождать **> 48 часов** (например 49ч). На время ожидания спайк лучше вести
   вне облачной сессии — контейнер эфемерный; зафиксировать `message_id`/время
   в задаче и вернуться позже.
3. Попробовать заменить медиа: `editMessageMedia` с новым фото на тот же
   `message_id`.
4. Зафиксировать результат:
   - **Успех** → жёсткого 48ч-лимита на медиа нет (или он мягче) → модал можно
     **упростить/убрать**, оставив честную обработку ошибки по факту.
   - **Ошибка** (напр. `Bad Request: message can't be edited`) → лимит реальный
     → модал с 3 вариантами **оставить**; в задаче записать точный текст ошибки
     и порог, на котором она появляется.
5. Параллельно проверить замену **только текста/подписи** (`editMessageCaption`)
   у того же старого поста — обычно она доступна дольше, чем замена фото; это
   обосновывает вариант «обновить только текст» в модале.

> Результат спайка (успех/ошибка + точный текст) дописать сюда после прогона.

## 6. SQL-примеры телеметрии бот-поиска (из FU5)

Таблица `bot_search_queries` (`backend/app/db/models.py:BotSearchQuery`):
одна строка на каждый выполненный поиск в боте / Inline Mode.

| Колонка | Тип | Смысл |
|---|---|---|
| `user_telegram_id` | BIGINT NULL | TG-id отправителя (часто аноним, без FK) |
| `source` | `'bot'` \| `'inline'` | путь поиска |
| `raw_text` | VARCHAR(200) | исходный текст запроса |
| `extracted_fields` | JSONB (список) | какие поля распознал парсер; **`[]` = ничего не распознано** (главный сигнал промаха) |
| `results_count` | INT | сколько объявлений нашли |
| `created_at` | timestamp (индекс) | retention 90 дней (`prune_bot_search_queries`) |

**Топ нераспознанных запросов за 30 дней** (кандидаты в словарь парсера):
```sql
SELECT raw_text, COUNT(*) AS hits
FROM bot_search_queries
WHERE extracted_fields = '[]'::jsonb
  AND created_at >= now() - interval '30 days'
GROUP BY raw_text
ORDER BY hits DESC
LIMIT 50;
```

**Доля пустых выдач по источнику** (качество выдачи):
```sql
SELECT source,
       COUNT(*)                                            AS total,
       COUNT(*) FILTER (WHERE results_count = 0)           AS empty,
       ROUND(100.0 * COUNT(*) FILTER (WHERE results_count = 0)
             / NULLIF(COUNT(*), 0), 1)                     AS empty_pct
FROM bot_search_queries
WHERE created_at >= now() - interval '30 days'
GROUP BY source;
```

**Miss-rate за месяц** (порог пересмотра rule-based → LLM из DECISION_MATRIX: > 10%):
```sql
SELECT ROUND(100.0 * COUNT(*) FILTER (WHERE extracted_fields = '[]'::jsonb)
             / NULLIF(COUNT(*), 0), 1) AS miss_pct
FROM bot_search_queries
WHERE created_at >= now() - interval '30 days';
```

**Объём по дням** (нагрузка / тренд):
```sql
SELECT date_trunc('day', created_at) AS day, source, COUNT(*)
FROM bot_search_queries
WHERE created_at >= now() - interval '14 days'
GROUP BY 1, 2
ORDER BY 1 DESC, 2;
```

## 7. Маркетинговые deep-link фильтры (из FU6 / D3)

Человекочитаемые ссылки, открывающие ленту TWA с применёнными фильтрами. Парсер
слага — `backend/app/services/deeplink.py:parse_filter_slug`.

**Формат:** `https://t.me/<bot>?startapp=filter_<slug>`

**Грамматика слага:** `<district>[_<N>rooms][_buy|_sale|_sell|_rent]`
- `<district>` — **обязателен**, идёт первым. Понимает алиасы и опечатки через
  общий словарь районов (`core/regions.py`): `chilonzor`, `chilanzar`,
  `чиланзар` — резолвятся в один район.
- `_<N>rooms` — опционально, 1–9 (`2rooms`, `3room`). Ставит `rooms_min=rooms_max=N`.
- сделка — опционально: `buy`/`sale`/`sell` → продажа, `rent` → аренда.
  (На фронте → `type=sell|rent`.)
- Токены комнат/сделки можно в любом порядке; первый «не-комнаты-не-сделка»
  токен с хвоста считается районом.
- Нераспознанный слаг (нет района) → лента без фильтров + 404 от резолвера +
  событие в аналитике (тихая деградация по D3).

**Примеры для маркетинга:**
| Ссылка | Что откроется |
|---|---|
| `t.me/ucharmarket_bot?startapp=filter_chilonzor_2rooms_rent` | Чиланзар, 2 комнаты, аренда |
| `t.me/ucharmarket_bot?startapp=filter_chilonzor_3rooms_buy` | Чиланзар, 3 комнаты, продажа |
| `t.me/ucharmarket_bot?startapp=filter_mirzo_ulugbek_rent` | Мирзо-Улугбек, аренда (комнаты любые) |
| `t.me/ucharmarket_bot?startapp=filter_yunusobod` | Юнусабад, без доп. фильтров |
| `t.me/ucharmarket_bot?startapp=filter_chilanzar_2rooms` | Тот же Чиланзар (латинская опечатка-алиас), 2 комнаты |

> Помимо `filter_`-слагов есть короткие `filter_<short-id>` (генерит бэкенд через
> `build_filter_link`) и остальные префиксы D3: `obj_<id>` (объявление),
> `ref_<id>` (реферал), `claim_<id>` / `agent_<id>` / `inv_<id>` (онбординг
> риелторов). Слаги — для печатной/баннерной рекламы, где ссылку набирают глазами.
