## Project Overview

This is a Telegram bot application that crawls messages from Telegram channels, extracts product information (including images), and sends it to a remote API for processing. The project consists of two main components:

1. **Crawler** (`crawler/`): Main production bot that monitors Telegram channels for product listings
2. **Extractor** (`extractor/`): Experimental NLP-based price/product extraction (not in production)

## Architecture

### Crawler Component
The production crawler (`crawler/Crawler.py`) uses Telethon library to:
- Listen to Telegram channels via event handlers (`@client.on(events.Album)` and `@client.on(events.NewMessage)`)
- Process two message types:
  - **Albums**: Multiple images with shared text description
  - **Single messages**: One image with text
- Extract text descriptions and download media from messages
- POST data to external API (`https://crawler.bsite.net/api/Crawler`)
- Upload associated images to listing endpoint

**Key Flow**:
```
Telegram Event → Extract text + username + messageId → POST to API →
Download media → POST images to listing endpoint → Cleanup temp files
```

### Configuration System
All Telegram API credentials are stored in `crawler/config.py`:
- `api_id`: Telegram API ID (from https://my.telegram.org)
- `api_hash`: Telegram API hash
- `phone_number`: Phone associated with account
- `session_name`: Session file name for Telethon

**IMPORTANT**: Never commit real credentials. The config.py contains placeholder values and should be populated per environment.

## Critical Implementation Details

### Message Filtering Logic
The crawler has specific skip conditions:
- **Albums without text**: Ignored (no description to extract)
- **Grouped messages in NewMessage handler**: Skipped to avoid duplication (handled by Album handler)
- **Messages without photos**: Ignored (product listings require images)
- **Photos without text**: Skipped (need description for product data)

### API Integration Pattern
1. **Text POST** (`SendPostText`):
   - Sends description, username, messageId
   - Returns response with `id` field used for image association

2. **Image POST** (`SendPostImage` or `SendPostImageByListingId`):
   - Downloads media to local temp file
   - Uploads to `/api/Crawler/listing/images` with `listingId`
   - Cleans up downloaded file after upload

### Event Handler Coordination
- `@client.on(events.Album)`: Handles grouped media (albums)
  - Processes first message for metadata
  - Iterates through all messages to upload images
- `@client.on(events.NewMessage)`: Handles individual messages
  - Checks `message.grouped_id` to avoid processing album items twice

### Session Management
Telethon sessions are persistent and stored as `.session` files. The session file name comes from `config.session_name`. If authentication fails or session expires, delete the session file and re-run to trigger re-authentication.

## File Organization Patterns

- Production code: `crawler/Crawler.py`
- Configuration: `crawler/config.py` (git-ignored credentials)
- Test/exploration: `crawler/test*.py`, `extractor/test.py`
- Dependencies: `requirements.txt` per component
- Sessions: `*.session` files (auto-generated by Telethon, should be git-ignored)

## Security Considerations

- **API credentials** in `config.py` are placeholders and must never contain real values in version control
- **Session files** contain authentication tokens and should be excluded from git
- Downloaded media files are temporary and cleaned up after upload to prevent disk bloat
- External API endpoints are hardcoded (`https://croller.bsite.net/...`) - verify endpoint security before production use

## Known Patterns and Conventions

- **Async/await**: All Telethon event handlers and media operations are asynchronous
- **Error handling**: Limited error handling present - production deployment should add comprehensive try/except blocks
- **Logging**: Uses `print()` statements - consider structured logging for production
- **Media cleanup**: Only `SendPostImage` deletes temp files with `os.remove(photo_path)`, `SendPostImageByListingId` does not (potential file leak)
