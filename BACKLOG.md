## 1. Вернуть табы на главную после запуска (по поведению пользователей)

**Контекст.** 2026-06-12 таб-бар «Лента / Подписки / Рекомендуемые» на главной
покупателя скрыт до запуска. Код закомментирован (НЕ удалён) в
`frontend/src/modules/buyer/pages/home/ui/page/Page.tsx` (блок `HomeTabBar`);
логика `$activeTab` / `tabChanged` в model не тронута, лента работает в режиме
«Лента» по умолчанию.

**Целевая модель — 2 таба:**

- **«Для вас»** — рекомендации системы.
- **«Подписки»** — объявления риэлторов, на которых подписан пользователь:
  сначала их объявления, когда закончились — остальные.

**Открытые вопросы:**

- порядок «остальных» объявлений после объявлений риэлторов из подписок;
- нужен ли визуальный разделитель между «объявлениями подписок» и «остальными»;
- есть ли уже follow риэлтора в системе (нужен анализ backend + frontend).

**Когда возвращаемся:** после запуска, по данным о поведении пользователей.

## 2. Доп. сортировки для недвижимости: «По площади» и «Цена за м²»

**Контекст.** 2026-06-12 сортировка вынесена из шторки фильтров в отдельную
строку на главной (счётчик «N объявлений» слева + кнопка-шторка справа). Дефолт
сменён с «Рекомендуемые» (по сути та же лента «сначала новые» + лёгкий буст под
анкету) на честное **«Сначала новые»**. Текущий набор: **Новые / Дешёвые /
Дорогие** (`newest` / `price_asc` / `price_desc` на `/listings/feed`).

**Что добавить позже (как у Cian/Krisha):**

- **«По площади»** — поле площади есть у всех трёх источников (`Listing.area`,
  `TelegramListing.area_sqm`, `OLXListing.area_sqm`); на `/listings/feed` нужна
  доработка сортировки/окна выборки по площади (по аналогии с price_asc/desc).
- **«Цена за м²»** — отложено сильнее: у Telegram/OLX-объявлений нет готового
  `price_per_sqm` (есть только у `Listing` для коммерции), считать на лету по
  «грязным» данным рискованно. Нужна оценка качества данных перед внедрением.

**Открытый вопрос:** нужен ли тумблер направления (площадь ↑/↓) или достаточно
двух пунктов «больше площадь» / «меньше площадь».
